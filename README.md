# Gym Bro

Приложение для зала: схема тела по объёму нагрузки, программы под своё время и
помощник, который читает твой реальный объём. Основа — мобильное приложение,
сайт остаётся витриной.

**Живой сайт:** https://derfi228.github.io/gym-bro/

Этот файл — память проекта. Здесь всё, что нужно, чтобы включиться в работу с
нуля: как запустить, как устроено, откуда взялись цифры и что менялось.

---

## Быстрый старт

Нужен Node.js 22+ и Git. GitHub CLI (`gh`) — только для работы с репозиторием.

```bash
git clone https://github.com/derfi228/gym-bro.git
```

Сайт:

```bash
cd web && npm install && npm run dev
```

Откроется на http://localhost:3000

Мобильное приложение (пока пустой шаблон Expo):

```bash
cd mobile && npm install && npx expo start
```

```
gym-bro/
├── web/                 сайт на Next.js 16 (App Router, TypeScript, Tailwind v4)
│   └── src/
│       ├── app/         page.tsx — оболочка приложения, globals.css — дизайн-система
│       ├── components/  Splash, icons, tabs/ — по вкладке на функцию
│       └── lib/         demo.ts — каталог упражнений, store.tsx — состояние
├── mobile/              приложение на Expo (React Native, TypeScript)
├── shared/              types.ts — общая модель данных для web и mobile
└── .github/workflows/   deploy.yml — автодеплой сайта на GitHub Pages
```

### Конвенции

- Весь код на TypeScript.
- **Модель данных меняется только в `shared/types.ts`**, синхронно для web и
  mobile. В web импортируется как `@shared/types` (алиас в `web/tsconfig.json`).
- Стили — только Tailwind (web) / StyleSheet (mobile), без inline-стилей.
- Дизайн — по `design-system.md`: тёмно-синий фон, **один** стальной акцент,
  тонкий сериф Cormorant в заголовках, кнопки-пилюли. Второй акцентный цвет не
  вводим; статусы различаем текстом, а не цветом.
- На сайте нет маркетинговых пояснений «почему мы выбрали эту фичу» — интерфейс
  говорит сам за себя.

## Как устроен сайт

Сайт сделан не лендингом, а витриной-приложением: заставка при входе, сразу
схема тела, переключение нижней панелью на 5 вкладок.

| Вкладка | Файл | Что делает |
|---|---|---|
| Тело | `tabs/BodyTab.tsx` | Фигура из 10 мышечных групп, заливка = набранный недельный объём |
| Упражнения | `tabs/ExercisesTab.tsx` | Каталог с фильтром по группам и сортировкой |
| Программа | `tabs/ProgramTab.tsx` | Список программ → программа → упражнение |
| GymBro | `tabs/GymBroTab.tsx` | Помощник, читает и меняет состояние приложения |
| Челленджи | `tabs/ChallengesTab.tsx` | Недельные задачи и серия с другом |

### Общее состояние — `web/src/lib/store.tsx`

Вкладки не изолированы, они работают с одним стором:

- **Отметка подхода** в «Программе» увеличивает объём мышцы → заливка на схеме
  тела растёт сразу. Целевой мышце +1 подход, вспомогательным +0.5.
- **GymBro** читает `loads` и собирает программу: отстающие группы первыми,
  перебранные (`ratio > 1`) пропускает. Программа попадает в список во вкладке
  «Программа», кнопка в ответе ведёт прямо в неё.
- **«Болит плечо»** добавляет ограничение и пересобирает программу без этой группы.

Языковой модели на сайте нет — логика подбора считается на месте. Когда
подключим настоящую модель, менять нужно только `GymBroTab` и `store`.

### Фигура человека

`BodyTab.tsx` рисует половину фигуры (`x < 160` в системе `viewBox 0 0 320 720`)
и зеркалит её через `translate(320,0) scale(-1,1)`. Поэтому:

- пути пишутся один раз и симметрия гарантирована;
- чтобы поправить мышцу, правь только левую половину.

Заливка «снизу вверх» — это `linearGradient` с жёсткой границей на уровне
`ratio`, отдельный на каждую группу.

## Откуда цифры в упражнениях

Это главное, чем каталог отличается от «взяли с потолка». У каждого упражнения
в `web/src/lib/demo.ts` есть поле `evidence`:

- **`emg`** — процент активации целевой мышцы по ЭМГ, относительно лучшего
  упражнения того же исследования. Есть для груди, трицепса.
- **`ranking`** — исследование опубликовало порядок, но не проценты. Бицепс,
  плечи, пресс.
- **`estimate`** — сравнительного исследования не нашли, значение экспертное.
  Ноги, трапеции, предплечья, косые.

### Важные оговорки

Их нельзя терять при доработке — иначе приложение начнёт врать:

1. **ЭМГ не предсказывает рост мышцы.** Активация в моменте и гипертрофия за
   месяцы — разные вещи. Vigotsky и соавторы разбирают это прямо:
   [Sports Medicine, 2022](https://link.springer.com/article/10.1007/s40279-021-01619-2).
   Цифры помогают выбрать между двумя упражнениями, но не обещают результат.
2. **Объём решает больше, чем выбор упражнения.** Мета-анализ Шонфельда:
   больше недельных подходов — больше роста, с выходом на плато
   ([PubMed](https://pubmed.ncbi.nlm.nih.gov/27433992/),
   [свежая мета-регрессия](https://pubmed.ncbi.nlm.nih.gov/41343037/)).
   Отсюда и вся модель «подходы из целевых» на схеме тела.
3. **Отдых между подходами: 3 минуты лучше 1.** Шонфельд, 2016 — длинные паузы
   дали больше силы и гипертрофии
   ([исследование](https://www.researchgate.net/publication/284711582_Longer_Interset_Rest_Periods_Enhance_Muscle_Strength_and_Hypertrophy_in_Resistance-Trained_Men)).
   Поэтому базе в программах ставится отдых 150 с, а не 60.
4. **Приседания и жим ногами по активации квадрицепса сопоставимы**, разница —
   в нагрузке на позвоночник и суставы. Не ставь присед выше «по науке».

## Деплой

Пуш в `main` с изменениями в `web/`, `shared/` или самом workflow запускает
`.github/workflows/deploy.yml`: сборка статики (`output: 'export'`) и публикация
на GitHub Pages.

Сайт живёт по адресу `/gym-bro`, поэтому в CI задаётся
`NEXT_PUBLIC_BASE_PATH=/gym-bro`. Локально переменной нет и сайт работает в корне.

Проверить последний прогон:

```bash
gh run list --limit 3
```
