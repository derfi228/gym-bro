# Gym Bro — контекст для Claude Code

Полная память проекта — в [README.md](README.md): структура, источники данных,
журнал изменений, что не сделано. Читай его первым, здесь только правила работы.

## Стек
- Сайт: Next.js 16 + TypeScript + Tailwind v4, деплой GitHub Pages (статический экспорт)
- Приложение: Expo (React Native) + TypeScript
- Бэкенд: Supabase — вход по почте и паролю, база с построчным доступом (RLS)

## Конвенции
- Весь код на TypeScript
- Модель данных менять только через `shared/types.ts`, синхронно для web и mobile.
  В web импорт через `@shared/types` — и ТОЛЬКО типы (`import type`). Псевдоним
  настроен для TypeScript, но не для сборщика: типы стираются до сборки, а
  значение из этого файла уронит сборку с «Module not found». Функции и
  константы кладём в `web/src/lib/`, даже если они про модель данных
- Стили только Tailwind (web) / StyleSheet (mobile), без inline-стилей
- Дизайн строго по `design-system.md`: тёмно-синий фон, ОДИН стальной акцент,
  тонкий сериф в заголовках, кнопки-пилюли. Второй акцентный цвет не вводить,
  статусы различать текстом, а не цветом.
  Единственное исключение — шкала объёма (`--color-idle`, `--color-warm`,
  `--color-over`): на карте тела нужно видеть недобор и перебор без чтения
  подписей. За пределами шкалы объёма эти цвета не использовать, и статус везде
  дублируется словом
- Сайт — витрина-приложение, а не лендинг. Маркетинговых пояснений вида
  «почему мы выбрали эту фичу» на сайте быть не должно

## База данных
Схема меняется ТОЛЬКО новой миграцией в `supabase/migrations`, файлы не
переписываются задним числом — в проекте они уже применены.

На каждой таблице обязателен RLS с политикой «только свои строки». Ключ, с
которым ходит сайт, публичный и лежит в браузере: без RLS данные открыты всем.
Таблица без RLS — это утечка, а не недоделка.

Служебный ключ `service_role` в код сайта и приложения не попадает никогда.
Его место — переменные серверных функций Supabase.

Таблицы заводятся под существующие функции. Пустая таблица «на будущее» —
это схема, которая разойдётся с кодом раньше, чем понадобится.

Названия полей в базе — в змеином регистре, в коде — в верблюжьем. Перевод
между ними делается в одном месте, на границе (`web/src/lib/auth.tsx`).

## Данные упражнений — не выдумывать
У каждого упражнения в `web/src/lib/demo.ts` есть поле `evidence`:
`emg` (процент из исследования), `ranking` (порядок без процентов) или
`estimate` (исследования нет). Добавляя упражнение, обязательно проставь
источник. Ссылки на исследования — в README, в интерфейсе только подпись.

Не терять оговорку: ЭМГ измеряет активацию в моменте и не предсказывает рост
мышцы. Объём и прогрессия важнее выбора упражнения.

## Карта мышц
Геометрия — в `bodyPaths.ts`, отдельно от компонента. Контуры взяты из
react-native-body-highlighter (MIT), условия лицензии в
`NOTICE-body-highlighter.txt` — не удалять. Файл сгенерирован, руками его не
править: чтобы поменять тело, перегенерируй целиком.

На группу приходится массив путей, левая и правая стороны заданы отдельно —
фигура НЕ зеркалится. Под мышцами лежит `BODY_OUTLINE` — контур тела целиком,
залитый фоном: без него промежутки между группами читаются как дыры и фигура
выглядит фрагментированной. Координаты общие для обеих проекций: спереди x 0..724,
сзади x 724..1448, поэтому viewBox разный (`VIEW_BOX`), а прямоугольник заливки
сдвигается на `CANVAS.width` для вида сзади.

Разделительной обводки цветом фона между путями быть не должно: она режет
мышцу на плитки. Обводка контуров — только с `vectorEffect="non-scaling-stroke"`
и в толщинах, заданных в пикселях экрана: фигура уменьшается втрое, и обычная
обводка становится тоньше пикселя, прорисовка пропадает. Проверять внешний вид
надо в реальном размере (~330 px), а не в увеличенном. Контур невыбранной группы — тонкий и приглушённый, тогда
внутренние пути читаются как волокна; границу показывает выбранная группа.

`MuscleFigure.tsx` — два режима: `fill` — заливка снизу вверх (объём),
`intensity` — равномерная яркость (вклад мышцы в упражнение). Заливка сделана
прямоугольником во всю фигуру, обрезанным `clipPath` по контуру группы: высота
задаётся переменной `--v` и потому анимируется. Цвет берётся из `statuses`.

`BodyPanel.tsx` — обёртка с легендой, поворотом и списком групп. Новые экраны
с телом собирать из неё, а не из `MuscleFigure` напрямую.

## Объём
`landmarks.ts` — единственный источник цифр по объёму: MEV / MAV / MRV на
группу, статусы, заливка. `volume.ts` — что даёт программа, разбор дисбалансов
и правки. Целевые значения нигде не дублировать, брать из `landmarks`.

Недельный диапазон нельзя прикладывать к одной тренировке: для сессии есть
`SESSION_SHARE`. Разбор дисбалансов считает неделю вместе с программой,
иначе он требует добавить всё подряд.

У каждой группы есть `basis`: `meta` — есть мета-анализ, `model` — только
ориентиры Israetel. Менять цифры без источника нельзя.

## Фичи приложения (MVP)
1. **Анализ тела и рекомендации по упражнениям** — классификация по
   эффективности, сложности выполнения и прорабатываемым мышцам.
2. **Схема человека на базе фото** — развитие мышцы по росту, весу, возрасту;
   заполненность показывает набранный объём, чтобы не было перетрена.
3. **Программы тренировок** с авто-отсчётом отдыха, заменой упражнения на ту же
   группу и произвольным временем тренировки.
4. **ИИ-помощник (вкладка GymBro, платная)** — генерирует программы, меняет их
   при боли, подбирает веса, оценивает реалистичность личной цели.
5. **Челленджи** — выполнимые недельные задачи, в том числе вдвоём с другом.
